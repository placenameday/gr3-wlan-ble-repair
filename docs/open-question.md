# 未解决的问题：为什么这项检查会失败？

## 已知

这台 GR III 的蓝牙和 Wi-Fi 在一次官方固件升级后失效，确切起始版本已记不清。到了官方 2.20，症状仍在。官方 2.20 的无线控制代码读取调整数据中的一个值，然后根据它决定该项检查是否通过。把这项检查固定为通过后，本机无线功能恢复。另一台 GR III 的公开 2.10 实机记录也出现过同一条禁用日志，但记录者没有确认其含义。 [社区实机记录](https://github.com/idontknownihil/gr3-film-mods/blob/main/FINDINGS.md#22a-camera-result-factory-mode-2026-10-08-entry-works-on-gr-iii-210)

## 可能的解释

| 假设 | 需要什么证据 |
| --- | --- |
| 调整数据原来存的值在升级或初始化期间变了 | 同一台相机升级前后、由原厂流程或已验证的只读方式取得的记录 |
| 存储内容没变，但固件读取失败、取到默认值，或对同一字段的解释变了 | 对比相关官方版本的字段读取、默认值和判定路径，并取得匹配的运行日志 |
| 问题原先已存在，恰好在升级后第一次做无线测试时发现 | 能确定同一台机身升级前后无线功能状态的记录 |

本机的日志导出没有产生文件，也没有升级前的调整数据备份。因此还无法确定是字段被改写、读取异常，还是其他原因。发反馈时，提供机型、升级前后版本、蓝牙配对和 Wi-Fi 热点表现即可。涉及序列号、MAC 或校准数据的完整文件请留在本机。
